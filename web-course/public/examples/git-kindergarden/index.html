📚 Глосарій Git

repository (repo)
Сховище вашого проєкту — весь код + вся історія змін.
commit
Збереження "знімку" коду. Як зберегти гру — можна повернутися до цього моменту.
branch (гілка)
Паралельна версія коду. Як чернетка документу — можна експериментувати, не зламавши оригінал.
main
Головна гілка — "продакшн" код, який працює на сервері.
develop
Гілка для збирання готових фіч перед випуском. "Тестовий полігон".
feature branch
Окрема гілка для конкретної задачі: feature/add-dates, feature/fix-login.
origin
Стандартна назва (alias) для вашого віддаленого репозиторію на GitHub. Як контакт у телефоні.
remote
Віддалений сервер (зазвичай GitHub), де зберігається "хмарна" копія репозиторію.
clone
Скопіювати весь репозиторій з GitHub на свій комп'ютер.
fetch
Перевірити, чи є нові зміни на remote. НЕ змінює ваші файли — тільки інформація.
pull
Завантажити зміни з remote І злити їх з вашою гілкою. fetch + merge в одній команді.
push
Відправити ваші коміти на remote (GitHub). Зробити їх доступними для інших.
staging area (index)
Проміжна зона перед комітом. Ви обираєте, які файли потраплять у наступний коміт.
git add
Додати файли до staging area. "Покласти в кошик" перед "покупкою" (комітом).
merge
Злити одну гілку в іншу. Об'єднати зміни.
merge conflict
Ситуація, коли Git не може автоматично злити зміни — дві людини змінили одне місце.
Pull Request (PR)
Запит на злиття вашої гілки. Інші перевіряють код + запускаються автоматичні тести.
code review
Процес перевірки чужого коду перед злиттям. Другий погляд = менше багів.
Conventional Commits
Домовленість, як підписувати коміти — не команда Git, а правило для людей. Підпис починається зі слова, що каже тип зміни: feat: — додав нове, fix: — виправив поломку, refactor: — переписав код без зміни поведінки, docs: — чіпав тільки тексти. Щоб потім можна було швидко знайти потрібне в історії.
CI/CD
Continuous Integration / Continuous Deployment — автоматичні тести + деплой при кожному злитті.
deploy (деплой)
Опублікувати код на сервері, зробити його доступним для користувачів.
rollback
Повернутися до попередньої робочої версії. "Ctrl+Z" для сервера.
Railway
Платформа для хостингу. Автоматично збирає і запускає ваш код з GitHub.
Cloudflare
Сервіс DNS + CDN. Направляє ваш домен (crm.example.com) на сервер Railway.
health check
Автоматична перевірка "чи живий сервер". Railway пінгає ваш додаток кожні N секунд.
hotfix
Терміновий фікс прямо в main, коли продакшн зламаний. Обходить звичайний процес.
flaky test
Нестабільний тест — то проходить, то падає. Причина: залежність від часу, мережі або порядку виконання.

⌨️ Git Cheat Sheet

Початок роботи

git clone <url>Клонувати репо
git statusПеревірити стан
git log --onelineІсторія комітів

Синхронізація

git fetchПеревірити remote
git pull origin developЗавантажити + злити
git push origin <branch>Відправити коміти

Гілки

git branchСписок гілок
git checkout -b <name>Нова гілка
git checkout <name>Перейти на гілку
git branch -d <name>Видалити гілку

Зміни

git add .Stage усіх змін
git add <file>Stage одного файлу
git commit -m "msg"Зберегти коміт
git diffПобачити зміни
git stashТимчасово сховати
git stash popПовернути сховане

Виправлення проблем

git pull origin developPush відхилено?
git log --mergeКонфлікти?
git reset HEAD <file>Unstage файл
git checkout -- <file>Скасувати зміни

⚠️ Ніколи не робити

git push --forceПерезапише чужу роботу!
git reset --hardВтратите всі зміни!
